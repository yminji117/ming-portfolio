Review requested 2026-08-20, before starting Phase 2 (sub-menu + detail pages: /works, /study, /about, /here guestbook), to check whether committed Phase 0/1 code (`src/lib`, `src/components`, migrations) is structurally ready to be reused/extended. No Critical or security bugs found. Main takeaway: **the data layer, not the components, is the real blocker.**

Key findings:
- `src/lib/data.ts` has **no slug-lookup functions** (`getProjectBySlug`, `getStudyBySlug`, etc.) and **no pagination/range support** (every `get*` takes a fixed `limit`, none use `.range()`/offset or return a total count). Every Phase 2 page (slug-based detail views, Works tab list with "load more") needs new functions added here — nothing to refactor, just additive, but confirms the PRD's tab-filter/pagination/detail requirements aren't covered by existing code at all.
- `src/components/currently-doing-section.tsx:40-41` already has a code comment acknowledging `ref_id` is a bare uuid PK with no slug join, deferring the project/study detail link to Phase 2 — consistent with the data-layer gap above, not a new finding, just confirms it's a known, intentional gap to close in Phase 2.
- No `dangerouslySetInnerHTML` anywhere in `src/` (verified via grep) — no XSS risk today. `Study.body` (jsonb `{ steps: [{label, text}] }`) is rendered as plain text via `{step.text}`, not injected as HTML. `Project` has no jsonb body field at all (`overview`/`result` are plain `string | null`) — if Phase 2 detail pages introduce a jsonb rich-text body for projects, there is no existing sanitization pattern in the codebase to copy from; would need to be designed fresh (or continue with a plain-string/structured-JSON approach like `Study.body` to avoid the sanitization problem entirely).
- `src/components/works-professional-grid.tsx` splits `projects` into `firstRow = slice(0,3)` / `secondRow = slice(3)` for its CSS-grid layout, but this works for *any* array length (not hardcoded to a fixed count) — reusable as-is for a full Works list page, contrary to what the review request suspected. Same for `works-side-grid.tsx` (plain `.map`, no count assumption). `study-section.tsx`'s single-open accordion + `moreHref` prop is Main-specific UX (not simply reusable for a full /study list), and its `studyHref()` sends items with `external_url` straight out to the external link instead of `/study/[slug]` — worth confirming this is the intended behavior for the full Study list page too, not just the Main summary section, before reusing it there as-is.
- `src/components/page-load-gate.tsx` is mounted once in `RootLayout` (`src/app/layout.tsx`) and gates first paint of the *entire app* behind "all `<video>` elements on the page are ready" (4s timeout fallback). Currently only the Hero video matters. If any Phase 2 detail page embeds `<video>` (e.g. project case-study media), that page's first paint will also be gated by this same site-wide logic — likely harmless due to the timeout, but worth being aware of since it's easy to forget this component exists when adding video to a new page.
- Confirmed the `enforce_featured_cap` caps in `0001_init.sql`/`0005_industry_and_caps.sql` (Professional 5 / Side 2 / Study 4) intentionally diverge from `PRD.md:787-789`'s older numbers (3/4/5) — `src/app/page.tsx` limits match the current trigger caps exactly, so this is stale PRD prose, not a code bug.
- Guestbook RLS (`0002_rls.sql`) already blocks anon `SELECT` on the raw `guestbook` table (`revoke select on guestbook from anon`) and exposes only `id, nickname, created_at, updated_at` via a `security_invoker = false` `guestbook_public` view — solid foundation for Phase 2's /here page. No password-check RPC or content-reveal server action exists yet, but that's expected new Phase 2 work, not a gap in existing code.

**Why:** confirms Phase 2 can safely build on top of existing `src/lib`, `src/components`, and migrations — the main required work is additive (new data.ts functions), not refactoring existing Main-page code. See [[project_phase1_main_page_review]] for the Phase 1 findings (now fixed) and [[project_phase0_supabase_review]] for the DB/RLS baseline.

**How to apply:** when Phase 2 PRs land, check that (1) new slug/pagination functions were added to `data.ts` rather than ad-hoc query logic in page components, (2) `currently-doing-section.tsx` got its slug join, (3) if a rich-text project body ships, verify how it's rendered (no `dangerouslySetInnerHTML` should appear without a sanitizer), (4) `study-section.tsx`'s external_url-bypasses-detail-page behavior was a deliberate choice for the full /study list too.
